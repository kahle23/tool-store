 关于 optimizer-base 插件

 描述：这是一个对 WordPress 开源系统进行一些 DIY 和 优化 的插件。该插件的配置方式为手动注释源代码或修改代码参数来进行的（代码参数一般不会涉及到逻辑方面的）。

关于版本控制和ID连续化的一些问题（Time：20160521）
首先，用WordPress写一篇文章，在点击[写文章]按钮后，会在数据库中创建一条文章状态为[auto-draft]的记录。WordPress写文章系统的脚本，会每隔一段时间判断文章内容是否有变化，如果有变化，则发送json包到服务器。如果是第一次发送的话（当然如果你在第一次间隔时间前点击了[保存草稿]亦会如此），会把文章状态从[auto-draft]改成[draft]，并且保存你现在的文章内容。然后每个一段时间都会判断是否变化，变化的话，就发送json包到服务器，服务器会把新发送来的json包中的文章内容覆盖到之前的那条草稿记录上，如果未变化的话，则不发送json包。总结：草稿内容的自动保存采用的是覆盖方式。

当草稿文章点击[发布]按钮后，会将表单数据再次json到数据库覆盖之前的那条草稿记录，并且把文章状态改成[publish]。

如果再次修改已经发布的文章的话，自动保存功能会创建一条新纪录，这条记录中保存的是修改前的文章内容。修改后的文章内容会覆盖原本的那条记录（自动保存在创建过新纪录之后，在点击[更新]按钮之前，都是修改后的文章内容覆盖之前的内容）。因此，文章被修改了，但是文章的ID还是不变的，但是会有新的ID来保存之前的版本。每次点击[更新]按钮前的自动保存，都只会创建一条新纪录，来保存之前的文章版本。当点击更新后，表示这篇文章修改成功。如果再次修改的话，又会创建一条新纪录以保存之前的版本。总结：每次修改发布后的文章，都会创建一条新纪录以保存之前的版本，修改的内容会覆盖原本的那条记录（自动保存），直到点击[更新]按钮为止。

如果有禁止版本控制的代码，但是没有禁止自动保存的代码。修改发布后的文章的话，只会创建一条新纪录，以保存之前的版本，即不管多少次的修改，总共只会创建一条版本控制的记录，用来保存之前的那个版本。

因此在本插件中，采用的是“禁止版本控制，有自动保存功能，每次创建新内容前，都先删除[auto-draft]和[inherit]状态的文章，并且让MySQL自动设置正确的自增值（最大的ID值加一）”。
